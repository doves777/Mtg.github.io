| Risk | Summary | Mitigation ideas |
| --- | --- | --- |
| **Market** | Existing tools already serve part of this market, so differentiation must be clear. | Lead with show-day speed + online pickup as the wedge. |
| **Operational complexity** | Card inventory is messy — variants, conditions, grading, sets, and pricing sources make normalization hard. | Start with pragmatic data model; iterate on attributes. |
| **Offline sync complexity** | Offline ordering can get technically complex, especially with multiple employees selling the same inventory. | Scope offline tightly for MVP; validate early. |
| **Pricing data dependency** | Dynamic pricing depends on reliable external market data, which may be expensive, limited, or inconsistent. | Begin with recommendations + manual approval. |
| **Buylist pricing** | Overpaying hurts margins; underpaying reduces submissions. | Guardrails, approval workflows, cash-vs-credit rules. |
| **Adoption** | Vendors may resist switching if setup requires too much data entry or operational change. | Minimize onboarding friction; strong import tooling. |
| **Event environment** | Card shows are chaotic — the product must be extremely fast and reliable, not just feature-rich. | Prioritize performance and offline resilience. |
